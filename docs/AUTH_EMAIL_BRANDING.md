# Harbourline Auth email branding

This runbook covers the authentication emails generated by Supabase Auth:

- email confirmation after password signup;
- magic-link sign-in; and
- password recovery.

These messages are separate from Harbourline's Edge Function lifecycle emails.
Changing `HARBOURLINE_FROM_EMAIL` changes the latter only; it does not change the
sender shown on Supabase Auth messages.

## Recommended provider: Resend SMTP

1. Verify the Harbourline sending domain in Resend before configuring Supabase.
   The controlled-beta setup uses the isolated `auth.harbourline.app` subdomain;
   the required DKIM/SPF records are recorded in
   [`PRODUCTION_ACTIVATION.md`](./PRODUCTION_ACTIVATION.md).
2. In the Supabase project, open **Authentication → SMTP Settings** and enable
   custom SMTP.
3. Enter the following non-secret connection settings:

   | Setting | Value |
   | --- | --- |
   | SMTP host | `smtp.resend.com` |
   | SMTP port | `465` |
   | Encryption | SSL/TLS |
   | Username | `resend` |
   | Sender name | `Harbourline Support` |
   | Sender email | A verified address on `auth.harbourline.app`, for example `support@auth.harbourline.app` |

4. Paste a dedicated Resend API key into the SMTP password field. Keep it in
   Supabase's encrypted project configuration only; never put it in the repo,
   browser variables, notes or chat.
5. Save the configuration and send Supabase's test message. Do not treat a
   successful save as delivery proof until the message is received and its
   headers show the verified Harbourline domain.

Resend documents the same relay as `smtp.resend.com`, with username `resend` and
an API key as the password. Port 465 is the recommended SSL/TLS option for this
setup.

## Brand the templates

In **Authentication → Email Templates**, update the **Confirm signup**, **Magic
Link** and **Reset Password** templates so the visible copy says Harbourline and
links to support. Preserve Supabase's required `{{ .ConfirmationURL }}` variable
in each template; do not paste a fixed token or a production URL in its place.

Suggested subjects:

- `Confirm your Harbourline email`
- `Your Harbourline sign-in link`
- `Reset your Harbourline password`

Use `Harbourline Support` as the visible sender name and keep the support
address consistent with the verified SMTP sender. Avoid including household
names, budget values or payment details in authentication messages.

## Acceptance check

For a disposable account:

- the message displays as **Harbourline Support** rather than **Supabase Auth**;
- the From address is the verified Harbourline address;
- the confirmation link returns to the approved Harbourline app URL;
- magic-link and recovery links still reach their respective flows; and
- SPF/DKIM pass in the received message headers.

This repository records the required configuration but cannot apply the hosted
Supabase Auth SMTP setting without project-admin access. The app source and
Edge Function Resend configuration are separate from that hosted gate.
